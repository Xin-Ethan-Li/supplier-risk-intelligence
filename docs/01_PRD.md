## 2. 产品背景

该项目将简历中 Supplier Risk Management（SRM）平台的核心技术能力重构为一个可公开展示、可本地复现、可在线交互的 Demo。原项目涉及供应商量化风险预测、非结构化文档检索、LLM 风险摘要、分数融合、容错编排和端到端遥测。

公开 Demo 不使用原企业数据、代码、模型或内部文档。所有数据必须来自明确标注的合成数据、虚构材料或允许公开使用的来源。Demo 是生产系统的参考实现，不宣称复刻原系统规模、SLA 或真实业务效果。

## 3. 产品目标

### 3.1 核心目标

1. 让访问者在 30 秒内理解项目解决的问题。
2. 让访问者在 2 分钟内完成一次供应商风险评估。
3. 同时展示结构化 ML、RAG、可解释性、后端工程和可靠性设计。
4. 提供公开 GitHub 仓库、完整 README、测试和一键本地运行方式。
5. 提供稳定的在线演示，不要求用户注册或提供 API Key。
6. 将项目接入个人 Portfolio，形成从简历到案例、代码、在线体验的完整路径。

### 3.2 成功标准

| 维度     | MVP 成功标准                               |
| -------- | ------------------------------------------ |
| 可理解性 | 首页清楚说明输入、处理过程和输出           |
| 可操作性 | 无需登录即可运行预置案例和自定义结构化输入 |
| 可解释性 | 返回主要风险因素及其方向和影响             |
| 可追溯性 | RAG 结论包含来源、日期和证据片段           |
| 可复现性 | 新开发者可依据 README 在 15 分钟内本地启动 |
| 质量     | 核心 API、模型封装和检索逻辑有自动化测试   |
| 部署     | Portfolio 与 Demo 均有公开 HTTPS 地址      |
| 透明度   | 明确声明数据、指标和部署均属于公开 Demo    |

## 4. 非目标

MVP 不包含以下生产级能力：

- 真实企业供应商数据接入。
- ERP、采购或支付系统集成。
- 实时新闻爬虫和商业数据订阅。
- 多租户、RBAC、SSO 或企业审计。
- 大规模在线训练或模型自动再训练。
- 面向公众的任意文件持久化。
- 对真实供应商做金融、法律或采购决策。
- 宣称达到原生产项目的 99.99% 可用性、P99 150ms 或真实预测效果。

## 5. 用户角色

### 5.1 HR / Recruiter

目标：快速确认候选人是否具备 AI、后端和云部署能力。

## 6. 核心用户流程

### 6.1 一键示例流程

1. 用户打开 Demo。
2. 系统展示三个预置供应商场景：低风险、中风险、高风险。
3. 用户选择一个场景。
4. 页面自动填充结构化指标和默认问题。
5. 用户点击 `Evaluate Supplier`。
6. 系统返回量化风险、文档风险、综合风险、风险因素、证据和延迟。

### 6.2 自定义评估流程

1. 用户输入交付延迟率、缺陷率等结构化特征。
2. 用户选择一个示例供应商文档集。
3. 用户输入风险问题。
4. 系统校验输入并执行评估。
5. 用户查看结果、展开证据、复制 Correlation ID。

### 6.3 技术深挖流程

1. 用户打开 `How it works`。
2. 查看在线请求路径、离线数据路径和技术架构图。
3. 查看模型与检索评估指标的定义。
4. 打开 GitHub、API 文档或 Portfolio Case Study。

## 9. 数据需求

### 9.1 结构化数据

- 完全合成并固定随机种子。
- 包含供应商、事件时间、预测时间和标签时间。
- 包含约 2% 高风险样本，用于展示类别不平衡问题。
- 特征只使用预测时间之前的信息。
- 使用时间切分，不使用随机划分作为最终测试。
- SMOTE 如被采用，只能在训练 Fold 内执行。

### 9.2 文档语料

- 使用虚构供应商名称，避免对真实公司产生风险判断。
- 覆盖财务、法律、质量、物流和运营事件。
- 每份文档包含来源等级、日期、类型和供应商 Metadata。
- 包含完全重复、近重复和版本更新样本，用于展示去重。
- 每个评估问题应有人工标注的相关证据。

## 10. 指标定义

### 10.1 ML 指标

- High-risk Recall
- High-risk Precision
- PR-AUC
- Confusion Matrix
- Threshold-dependent business trade-off

Accuracy 仅作为辅助指标，不作为主指标。

### 10.2 Retrieval 指标

- Recall@5：至少一个正确 Evidence 是否出现在 Top-5。
- MRR：第一个正确 Evidence 的排名。
- Retrieval latency：Query Embedding 完成后的搜索与排名时间。

### 10.3 在线服务指标

- 请求成功率
- P50 / P95 / P99 延迟
- 模型推理延迟
- 检索延迟
- Provider 延迟和超时
- Fallback 次数
- Cache hit rate

公开页面只展示 Demo 实测指标，不将原生产指标冒充为本项目结果。

## 11. 非功能需求

### 11.1 性能目标

| 场景                      | MVP 目标        |
| ------------------------- | --------------- |
| XGBoost 推理              | P95 < 50ms      |
| 预构建语料检索            | P95 < 200ms     |
| 不调用外部 LLM 的完整评估 | P95 < 1.5s      |
| 调用外部 LLM 的完整评估   | P95 < 6s        |
| 静态页面首屏              | 正常宽带下 < 2s |

### 11.2 安全与隐私

- 无需登录，但必须设置 IP 限流。
- API Secret 只存储在服务端环境变量。
- CORS 只允许 Portfolio 和 Demo 域名。
- 不记录完整用户输入或敏感文本。
- MVP 不持久化用户输入。
- 限制文本长度、请求体大小和处理时长。
- 所有生成式输出执行 Schema 和 Citation Validation。
- 错误响应不得泄漏堆栈、内部路径或 Secret。

### 11.3 可访问性与兼容性

- 支持键盘操作和明显的 Focus 状态。
- 风险状态不能只依赖颜色表达。
- 图表提供文本替代。
- 支持最新稳定版本的 Chrome、Edge、Firefox 和 Safari。
- 支持常见手机宽度。

## 12. MVP 验收标准

MVP 只有在以下条件全部满足时才视为完成：

- 三个预置案例均能得到稳定结果。
- 自定义结构化输入可完成评估。
- 结果包含综合风险、模型风险、文档风险和解释。
- 每条文档结论都能追溯至返回的证据。
- 无证据时不会编造引用。
- API 对非法输入返回结构化 4xx 错误。
- 核心测试在 CI 中通过。
- Docker Compose 可以启动本地开发环境。
- GitHub README 可独立指导运行和理解项目。
- 公开 Demo 使用 HTTPS，且无需登录。
- Portfolio 中存在 Case Study、Live Demo 和 GitHub 链接。
- 页面明确声明合成数据、用途和限制。

## 13. 风险与缓解措施

| 风险                | 影响               | 缓解措施                                                 |
| ------------------- | ------------------ | -------------------------------------------------------- |
| Demo 与简历指标冲突 | 损害可信度         | 区分原项目描述和 Demo 实测指标                           |
| 合成数据过于简单    | 模型展示缺乏说服力 | 加入时间趋势、噪声、类别不平衡和数据字典                 |
| RAG 输出幻觉        | 错误引用           | Evidence-bound Schema、Citation Validation、无证据拒答   |
| 免费服务冷启动      | HR 首次体验差      | 使用低成本常驻实例或预热状态提示                         |
| LLM 费用滥用        | 账单风险           | 默认确定性摘要、限流、缓存、预算和熔断                   |
| 架构过度复杂        | 延期               | 先交付 P0，PostgreSQL/Redis/完整 Milvus 作为增强 Profile |
| PDF 上传安全        | 服务资源和隐私风险 | MVP 不开放任意 PDF；P2 再引入隔离处理                    |
